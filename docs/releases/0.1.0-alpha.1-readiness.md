# Replica 0.1.0-alpha.1 release readiness

- Assessment date: 2026-08-11
- Candidate: `0.1.0-alpha.1`
- Target: Windows 11 `win-x64`, self-contained WPF application
- Tag: not created, as required for this preparation step

## Decision

**Public Alpha Release Ready: No.**

The source, automated feature scenarios, package build, checksum, and isolated Installer smoke test pass. No Critical code defect was found. Public publication remains blocked by the human-driven end-to-end recovery and accessibility walkthrough, explicit acceptance of the unsigned Alpha, and public-repository security/governance decisions listed below.

This is a readiness assessment, not authorization to create `v0.1.0-alpha.1` or publish a GitHub Release.

## Code review

- No `TODO`, `FIXME`, `NotImplementedException`, `Dummy`, `Console.WriteLine`, debug trace, or debug-only branch was found in tracked product code.
- No user-specific hard-coded absolute path was found in production code. Fixed Windows registry locations, well-known system paths, installer locations, and synthetic test paths are intentional.
- No credential-like literal, private-key header, GitHub token, or AWS access-key pattern was found in production/source documents. Security terminology appears in redaction and exclusion code as expected.
- External process execution uses typed operations, fixed executable identities, fixed or validated argument lists, cancellation, timeouts, captured exit codes, and bounded output. No arbitrary `ShellCommand` action exists.
- PowerShell inventory commands are fixed implementation constants selected by enums; Snapshot or user text cannot become command source.
- Elevation uses `runas` only for the same `Replica.exe`, a checksum-protected expiring single-use Plan, and the administrator-action allow-list. The normal UI remains unelevated.
- Catch blocks either report partial failure, rethrow, return a safe value, or document bounded best-effort cleanup. Empty cleanup/detection catches found during review were annotated with their safety rationale.
- Automated coverage exists for the requested release scenarios, security boundaries, cancellation, timeout, partial failure, and Installer contracts.

## Experimental

Everything in `0.1.0-alpha.1` is experimental. Snapshot schema compatibility, built-in plugin version support, matching confidence, recovery coverage, UI copy, accessibility details, and update behavior may change before Beta. Users must keep original data and an independent backup and should test only on non-critical environments.

Replica is not a disk image and cannot recreate credentials, authentication state, hardware drivers, paid licenses, unsupported settings, or files that were not explicitly selected.

## Known issues

- The Installer is not Authenticode-signed. Windows can show an unknown-publisher warning.
- Only Windows 11 `win-x64` is supported.
- A live, human-driven current-PC scan, Snapshot creation/open, post-reset recovery, rollback, Korean/English UI, keyboard, screen-reader, DPI, and high-contrast walkthrough has not been completed on a clean release VM.
- Low/Unknown application matches, unsupported versions, hardware-dependent settings, and unavailable packages require manual action.
- Extra applications are never automatically removed; downgrades and application uninstall rollback are not automatic.
- Credentials, browser profiles, private keys, license state, drivers, complete WSL disks, containers, volumes, large content libraries, and broad user-profile locations are excluded.
- GitHub Private Vulnerability Reporting is not enabled. [SECURITY.md](../../SECURITY.md) currently documents a limited private-contact fallback.
- No project license has been selected. The repository is not offered under an open-source license.
- The repository is currently private, so a GitHub Release would not yet be a public distribution channel for normal users.

## Security

- Archive traversal, absolute paths, duplicate entries, reparse points, decompression limits, JSON limits, checksum mismatch, encryption failure, recovery path attacks, elevated-Plan tampering/replay, untrusted plugin artifacts, package identifier injection, update Asset validation, and rollback integrity have regression coverage.
- Dependency audit reported no known vulnerable packages from the configured NuGet source at assessment time.
- Telemetry is not shipped. Logs exclude exception messages, secrets, environment values, Snapshot passwords, and file contents.
- The isolated Installer smoke test ran with Sandbox networking and clipboard disabled.
- CodeQL remains configured but is intentionally skipped while the private repository lacks the required GitHub Code Security setting.

## Blocking problems

Before creating `v0.1.0-alpha.1` or publishing a public Alpha Release:

1. complete and record the human-driven clean-VM scan-to-recovery, rollback, localization, and accessibility walkthrough;
2. explicitly approve publishing an unsigned Alpha and preserve the prominent warning and SHA-256 Asset;
3. decide when the repository becomes public so GitHub Releases can serve normal users;
4. enable GitHub Private Vulnerability Reporting or establish and document another verified private security contact;
5. confirm the no-license status is the intended legal posture for the public source and Installer;
6. rerun CI from the final reviewed commit, then create the annotated tag in a separate authorized release step.

No Critical implementation defect is known from this assessment. The blocking items are release-validation, distribution, security-contact, and governance gates; therefore this candidate is technically buildable but is not marked Public Alpha Release Ready.
