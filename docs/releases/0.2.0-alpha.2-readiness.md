# Replica 0.2.0 Alpha 2 readiness

> **Outcome:** Not published. The immutable candidate tag exposed two fail-closed Windows PowerShell 5.1 release-automation defects before any official GitHub Release was created. The candidate is superseded by `v0.2.0-alpha.3`; the `alpha.2` tag is not moved or reused.

## Candidate

- Version: `0.2.0-alpha.2`
- Intended tag: `v0.2.0-alpha.2`
- Channel: GitHub pre-release
- Platforms: Windows 11 x64 recovery client; macOS 13+ ARM64/x64 read-only Preview

## Scope

Alpha 2 completes the production-quality recovery experience implemented after Alpha 1. It adds end-to-end Offline Recovery Pack authoring and bounded export, strengthens snapshot/trust binding and hostile-input handling, clarifies the beginner recovery workflow, and hardens elevation, rollback, installer/update, plugin-privacy, and release-signing boundaries.

The macOS client remains explicitly read-only. Its packages are produced for Apple Silicon and Intel, but it does not expose Windows recovery execution as though it were supported.

## Verification

- Pull request #34 completed Windows build/test, macOS ARM64 build/test/DMG, macOS x64 build/test/DMG, and CodeQL successfully on the final commit.
- The final automated suite passed 457 tests: 54 integration, 133 core, 27 macOS, and 243 infrastructure tests.
- Release packaging contract checks cover immutable tag ancestry, isolated signing jobs, prepared-artifact manifests, Inno compiler tree/signer pins, Windows publisher pinning, Apple certificate pinning, and checksum verification before publication.
- macOS packaging now uses separate architecture runners and explicit DMG capacity headroom after reproducing and correcting the previous runner disk and image-sizing failures.
- Windows release checks remain compatible with the Windows PowerShell 5.1 shell used by the hosted runner.
- No vulnerable NuGet package was reported across the solution during the final pull-request verification.

## Security and trust posture

- The release workflow fails closed if an immutable annotated tag is not reachable from the current default branch.
- Credential-free runners build and test prepared application bytes; fresh packaging runners revalidate them before any protected signing identity can be imported.
- Alpha permits an unsigned Windows installer and ad-hoc-signed, non-notarized macOS DMGs only when the GitHub Release notes state that trust posture prominently and matching SHA-256 files are published.
- Stable remains blocked unless Windows Authenticode and Apple Developer ID signing/notarization both succeed with reviewed public certificate pins.

## Known limitations accepted for Alpha

- Production Windows and Apple signing/notarization credentials are not configured.
- The macOS Preview cannot create Recovery Snapshots, decrypt password-protected Snapshots, execute restore plans, or roll back changes.
- Clean Windows 11 VM recovery, rollback, install/upgrade/uninstall, and representative Apple Silicon/Intel interactive accessibility checks remain human validation work.
- No project license has been selected. The source is publicly visible but is not offered under an open-source license.
- Hardware drivers, credentials, authentication sessions, paid licenses, private keys, browser profiles, entire WSL disks, containers, volumes, and unsupported application state remain outside automatic recovery.

## Release decision

Ready for the `v0.2.0-alpha.2` GitHub pre-release after this focused release-preparation change is merged and its required CI checks pass. The version must not be promoted or described as Stable, and the release workflow must publish no partial release if packaging or verification fails.
